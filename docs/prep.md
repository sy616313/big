## 二、本地还是并行科技：为什么选本地

本机实测：

| 项 | 实测 | ACT 训练需要 | 判断 |
|---|---|---|---|
| 显卡 | RTX 5070 Laptop，8GB 显存，算力 sm_120 | 峰值显存 2–6GB | 够，还留余量 |
| CPU / 内存 | Ultra 9 275HX 24 核 / 31GB | 4 核 / 16GB 起 | 富余 |
| 硬盘 | D 盘剩 392GB | 留 50–100GB | 够 |
| 驱动 | 573.24，支持 CUDA 12.8 | cu128 轮子 | 匹配 |

**结论：本地跑主训练。** 50 条演示数据，RTX 4090 上大约 30–60 分钟；你这张 5070 预计 1–2 小时，完全在可接受范围。

**云端只在这三种情况下才用：**

1. 要**同时**试 3 组以上超参，本地串行太慢；
2. 本地显存被别的东西占着（比如同时开游戏/剪辑）；
3. 需要一张卡长时间挂着跑，而你要合盖带走电脑。

**云端的六条纪律**（并行科技这类按卡时计费的平台通用）：

1. 先确认镜像里 PyTorch 是 **CUDA 12.8 及以上**，否则 5070 跑不了（见第五节坑 2）。
2. 代码用 git 拉，不要靠本地打包上传 —— 上传慢还容易漏文件。
3. 数据量很小（50 条 episode 通常几百 MB），直接传；别去挂什么共享盘。
4. **训练结束第一件事：把 `runs/` 下载回来。** 实例一释放，权重就没了。
5. 跑之前先 `torch.cuda.is_available()` 打印一行，确认卡认出来了再开训，别浪费卡时。
6. 记下镜像名、torch 版本、启动命令，下次重建不用重新摸。

## 五、已知的坑（先记住，能省一天）

1. **系统 Python 是 3.13 / 3.14，不能用。** MuJoCo、LeRobot 的依赖在这两个版本上很容易编译失败。一律用 `embodied` 环境。
2. **RTX 5070 是最新架构 sm_120。** 装成 cu121 的 PyTorch 会报 `no kernel image is available for execution on the device`，这不是代码错，是轮子架构不对。必须 cu128。
3. **huggingface.co 直连不通**（实测超时），但 `hf-mirror.com` 和 `modelscope.cn` 通。下载模型/数据集前先设：
   ```powershell
   $env:HF_ENDPOINT = "https://hf-mirror.com"
   ```
4. **conda 环境在 C 盘**，C 盘剩 161GB，装 2–3 个环境没问题，但数据集和权重放 D 盘。
5. **路径里有中文**（`D:\大挑战者杯校赛`）。多数 Python 库没问题，但个别 C++ 扩展会炸；真遇到就换成纯英文路径再试。
