## 三、现在的状态（全部新场景，2026-11-09 12:30）

| 项 | 数字 | 说明 |
|---|---|---|
| 机器示范 300 条模型 | **100%**（50 局） | 链路对照 |
| 人类 **74** 条模型 | **56%**（80 局） | 两组种子 40000 / 70000 各 40 局 |
| 人类 **104** 条（不加增强） | **65%**（80 局） | 68% / 62% |
| 人类 104 条 + 图像增强（20k 步） | **75%**（80 局） | 72% / 78% |
| **人类 154 条 + 图像增强（40k 步）** | **76%**（80 局） | **78% / 75%** ← 当前最优 |
| 人类 104 条 + 增强 + 40k 步 | **54%**（80 局） | **过拟合，别这么训** |
| 遮住画面（104 模型） | 0/20 | 证明策略真在看图 |
| 抹掉关节角 | 0/20 | 证明也用本体感觉 |
| 策略 + 大模型兜底 | 100/100 | 其中 36 局靠"看失败→换方案"救回 |

**最优配置**：`chunk_size=40`、每 10 步重规划、**训练 20k 步（不是越多越好）**、batch 16、**开图像增强**。

**数据量 / 配置曲线**（PPT 核心素材）：
```
14 条 20%   20 条 28%   29 条 48%   44 条 55%
74 条 59%（chunk 100） → 56%（chunk 40，80 局）
104 条 65%（80 局） → 75%（+图像增强） → 54%（步数瞎加到 40k，过拟合）
154 条 + 增强 + 40k（42 遍）→ 76%      ← **饱和了**：多 50 条只涨 1 个点
```

**第三条（今天下午刚踩出来的）**：**训练步数要跟着数据量走，看"遍历遍数"不是"步数"。**
104 条 × 20k 步 = 31 遍 → 75%；104 条 × 40k = 63 遍 → 54%（过拟合）；
154 条 × 20k = 21 遍 → 46%（欠拟合）。换成 40k（42 遍）才和 104 条那次可比。

**第四条（今天傍晚找到的最大突破）：多模型集成，76% → 84%。**
两个独立训练的模型各自预测，动作取平均，在同样 80 局上从 76% 抬到 **84%**（82% / 85%），
平均步数从 166 降到 146。原因是它们的误差里随机成分不同，平均能抵消。
**但成员质量必须相当**：把 66% 的 50k 模型加进去，三个模型反而掉到 75%。

**两条最值钱的经验**（都不是"多堆数据"）：
1. **一次预测多长**：chunk 100 → 40，同样数据 +10 点，且"重规划越勤越好"（每 10 步最优）。
2. **图像增强**：一个开关 +10 点（`--dataset.image_transforms.enable=true`），比再采 100 条还划算。
   反过来说：**训练步数不能瞎加**，104 条数据训 40k 步会从 75% 掉到 54%。

失败构成（104 模型，80 局）：没夹起来 15、放偏 9、没松手 4 —— 主因仍是抓取精度。
根因量过：模型抓取点误差约 **14 mm**，任务容差只有 **10 mm**（`scripts/measure_tolerance.py`）。

- 换机重跑前先跑 `scripts/diagnose_data.py`：自带自检，机器示范回放必须 100% 才往下走
- `scripts/diagnose_policy.py` 的 P1 是相对判据：满分模型的误差必须明显小于扣分模型
