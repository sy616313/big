|---|---|---|

| 人类 **104** 条（不加增强） | **65%**（80 局） | 68% / 62% |
| 人类 104 条 + 图像增强（20k 步） | **75%**（80 局） | 72% / 78% |
| 人类 154 条 + 图像增强（40k 步） | **76%**（80 局） | **78% / 75%** |
| 人类 104 条 + 增强 + 40k 步 | **54%**（80 局） | **过拟合，别这么训** |
| **A + B 两模型集成（定稿）** | **75.6%**（160 局） | **121 / 160**，四组新场景 |

注意前六行的 80 局都来自 40000 / 70000 这两组种子；换成 90000 / 100000 会低 10–15 个点，
所以**对外只报最后那个 160 局的数**。原因见下面第四条。

**最优配置**：`chunk_size=40`、每 10 步重规划、batch 16、**开图像增强**；
训练步数按数据量定，不看绝对步数看"遍历遍数"——104 条用 20k（31 遍），154 条用 40k（42 遍）。

**数据量 / 配置曲线**（PPT 核心素材）：
```
14 条 20%   20 条 28%   29 条 48%   44 条 55%
74 条 59%（chunk 100） → 56%（chunk 40，80 局）
104 条 65%（80 局） → 75%（+图像增强） → 54%（步数瞎加到 40k，过拟合）
154 条 + 增强 + 40k（42 遍）→ 76%      ← **饱和了**：多 50 条只涨 1 个点
```

**第三条（今天下午刚踩出来的）**：**训练步数要跟着数据量走，看"遍历遍数"不是"步数"。**
104 条 × 20k 步 = 31 遍 → 75%；104 条 × 40k = 63 遍 → 54%（过拟合）；
154 条 × 20k = 21 遍 → 46%（欠拟合）。换成 40k（42 遍）才和 104 条那次可比。

**第四条：多模型集成有用，但只在前 80 局上"看起来"到了 84%。**
两个独立训练的模型各自预测、动作取平均，在 40000/70000 两组种子上 80 局从 76% 抬到 83.8%（82% / 85%）。
把这套方案换到 90000/100000 两组新场景上重跑，只有 67.5%。查过场景几何——四组的方块半径、
夹角、方块到盘子的间距几乎一样（0.203–0.208 m / 0.137–0.154 m），所以不是"后两组更难"能解释的。
真实原因是成功率本来就压在容差线上（抓取点误差 14 mm vs 容差 10 mm），换个场景，同一套动作就跨过成功线。

**所以所有数字一律按 4 组共 160 局报**（原始输出在 `runs/logs/ensAB_*.log`、`runs/logs/retry_*.log`）：

| 方案 | 160 局 | 备注 |
|---|---|---|
| A：人类 154 条 + 增强（40k） | 108/160 = 67.5% | 单模型 |
| B：人类 104 条 + 增强（20k） | 111/160 = 69.4% | 单模型 |
| D：A 的同配方换随机种子 | 113/160 = 70.6% | 单模型里最好 |
| **A + B 集成** | **121/160 = 75.6%** | **采用** |
| B + D 集成 | 116/160 = 72.5% | |
| A + D 集成 | 107/160 = 66.9% | 两个同源模型，平均后比单个还差 |
| A + B + D 集成 | 109/160 = 68.1% | 三个模型不如两个 |

两条从集成本身学到的：
1. **成员要"错得不一样"**。A 和 D 是同配方换种子，错误高度相关，平均没收益（66.9%）；A 和 B 数据不同，才有 +6 点。
2. **"三个模型更差"其实是权重问题，不是数量问题**。D 和 A 几乎一样，所以 A+B+D ≈ 0.67·A + 0.33·B。
   同一批 40 局验证：50:50 是 82%，67:33 是 75%，33:67 是 72%。**均衡才是关键**，
   要上三个模型，第三个必须跟 A、B 明显不同。

**第五条（今晚定的对外口径）：单次 75.6%，允许重试到 91.2%。**
两个模型的失败场景并不重合：160 局里"集成失败但单独某个模型能成"的有 25 局。所以按
**A+B → A → B** 的顺序试（每次先复位到同一局），成功率 146/160 = **91.2%**
（一次就成 121 局、两次 14 局、三次 11 局）。脚本 `scripts/eval_retry.py`，网页里
`grasp_and_place` 已经是这个行为（失败会在同一局复位换模型再抓）。

对外只说三句话，别混：
- 单次 75.6%（160 局）——这是"策略本身有多强"
- 最多 3 次 91.2%（同样 160 局）——这是"系统允许失败重来后有多强"
- 策略 + 解析专家兜底 100/100——备用方案的功劳，不是学习的功劳

**刀尖上跳舞这件事要说清楚**：三个模型的预测动作只差 0.6–1.0 度（实测 A vs B 平均差 0.016 rad），
但 160 局里约 25 局结局会翻转。原因是抓取容差 10 mm、模型误差 14 mm，成功率本来就压在线上。
所以别再指望靠微调集成权重挤点数——要么减小误差（更好的数据/更大的模型），要么允许重试。

**两条最值钱的经验**（都不是"多堆数据"）：
1. **一次预测多长**：chunk 100 → 40，同样数据 +10 点，且"重规划越勤越好"（每 10 步最优）。
2. **图像增强**：一个开关 +10 点（`--dataset.image_transforms.enable=true`），比再采 100 条还划算。
   反过来说：**训练步数不能瞎加**，104 条数据训 40k 步会从 75% 掉到 54%。

失败构成（104 模型，80 局）：没夹起来 15、放偏 9、没松手 4 —— 主因仍是抓取精度。
根因量过：模型抓取点误差约 **14 mm**，任务容差只有 **10 mm**（`scripts/measure_tolerance.py`）。

### 网页演示怎么用（评委面前就按这个走）

- **模式**：左上「智能体模式 / 手动模式」二选一，随时能切（切到手动会把还在跑的大模型任务直接中止）
- **智能体模式**：输入框打一句话 → 执行；下面一块显示「你说 / 计划 / 执行」，每一步的真实结果都在
- **手动模式**：方向键前后左右、PageUp/PageDown 升降、空格开合爪子（按住连续动）；
  页面上也有对应的按钮，鼠标就能开
- **暂停**：随时冻结物理（画面继续走，但方块不动），暂停时也能切模式；「继续」恢复
- **换个场景**：重新随机方块和盘子的位置（和训练/评估同一套采样规则），证明不是摆拍
- **同一局重来**：场景不变，机械臂回待机位
